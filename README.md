# Telegram → Google Drive

Бот для Ubuntu 24.04 LTS / Python 3.12. `/start` отвечает «Привет!»; фото и видео сохраняются в Google Drive в подпапки `<Telegram user ID>`. Последующие загрузки попадают в ту же папку, включая после перезапуска. Подписи к файлам не сохраняются. Альбом обрабатывается как несколько файлов. Документы принимаются только с MIME image/video и распознаваемым заголовком JPEG, PNG, WebP, MP4/MOV, WebM/MKV или AVI. Прочие сообщения, документы и анимации игнорируются. Имена файлов генерирует бот, пользовательские пути не используются. MOV и MKV сохраняются с расширениями MP4 и WebM соответственно; перекодирования нет.

Ограничение стандартного Telegram Bot API: скачивание до 20 MB. Большие видео не сохраняются, бот сообщает об ограничении. Для несжатых фотографий отправляйте их как файл. Место на Google Drive должно быть доступно. Бот работает только в личных чатах. По умолчанию доступ открыт всем; для личного использования обязательно заполните `allowed_user_ids`.

## 1. Telegram

1. Откройте проверенный аккаунт **@BotFather** в Telegram.
2. Выполните `/newbot`, задайте имя и уникальный username с окончанием `bot`.
3. Полученный токен храните как пароль. Не отправляйте его в чат и не добавляйте в Git. При утечке отзовите через BotFather `/revoke`.
4. В дальнейшем вставьте токен в `telegram.token` конфигурации на сервере.
5. Используйте отдельного бота, который не запущен в другом месте. Приложение использует long polling; webhook ему не нужен. При конфликте с прежним webhook удалите его через Telegram Bot API `deleteWebhook` безопасным локальным инструментом, не размещая токен в истории shell/URL браузера.

## 2. Google Drive: OAuth на своём компьютере

Обычный сервисный аккаунт не подходит для загрузки в личный Drive: у него нет личной дисковой квоты. Здесь используется OAuth вашего аккаунта. Серверу браузер не нужен.

1. Откройте https://console.cloud.google.com/ и создайте проект.
2. В **APIs & Services → Library** включите **Google Drive API**.
3. В **Google Auth Platform** (либо OAuth consent screen) настройте Branding, Audience и Data Access. Добавьте scope `https://www.googleapis.com/auth/drive.file`. Он даёт доступ к файлам, созданным приложением, а не всему диску.
4. Для External в Testing добавьте свой Google-аккаунт в Test users. **В Testing refresh token для Drive обычно истекает через 7 дней**. Для постоянной работы переведите приложение в Production; выполните требования Google, если консоль запросит проверку. Для личного приложения возможен экран предупреждения; продолжайте только для своего проекта. Workspace может требовать разрешение администратора.
5. В Clients создайте OAuth Client ID типа **Desktop app** и скачайте JSON. Не выбирайте Web application.
6. На своём компьютере с браузером и Python 3.11+ выполните:

```bash
git clone https://github.com/nistratovd/BotImagesSave.git
cd BotImagesSave
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/google_auth.py /путь/к/client_secret.json --output /безопасный/путь/token.json
```

Откроется браузер. Войдите в нужный Google-аккаунт и разрешите доступ. Helper создаст папку **Telegram media**, выведет её `root_folder_id` и сохранит OAuth token. Используйте именно эту папку: произвольная ранее созданная папка может быть недоступна при scope `drive.file`. Не удаляйте папку и не меняйте OAuth-проект. Каждый повторный запуск helper создаёт новую корневую папку; для сохранения архива сохраните прежние token и ID.

7. Передайте `token.json` на сервер через SCP/SFTP в закрытый каталог своего пользователя, затем установите его командой из следующего раздела. Удалите промежуточную копию. OAuth JSON содержит refresh token и client secret: не публикуйте его. Резервную копию храните зашифрованной.

## 3. Установка на Ubuntu 24.04

Команды выполняются по SSH. Сначала убедитесь, что код находится в вашем Git-репозитории: этот проект не публикует изменения автоматически.

```bash
sudo apt-get update
sudo apt-get install -y git python3-venv ca-certificates
git clone https://github.com/nistratovd/BotImagesSave.git
cd BotImagesSave
sudo bash scripts/manage.sh install
sudo install -o root -g botimagessave -m 640 ~/token.json /etc/botimagessave/secrets/token.json
rm ~/token.json
sudoedit /etc/botimagessave/config.toml
```

Конфигурация:

```toml
[telegram]
token = "токен от BotFather"
greeting = "Привет!"
allowed_user_ids = [] # либо [123456789, 987654321]

[google]
token_file = "/etc/botimagessave/secrets/token.json"
root_folder_id = "ID, выведенный helper"

[storage]
max_file_mb = 20
```

Числовой ID пользователя можно узнать из собственного Telegram-клиента/API или у доверенного инструмента. Username не является ID. Не публикуйте конфигурацию.

```bash
sudo bash scripts/manage.sh start
sudo bash scripts/manage.sh status
sudo bash scripts/manage.sh logs
```

После изменения TOML используйте `restart`. Google Drive проверяется перед стартом polling; при недоступной папке служба завершится с ошибкой. `start` включает автозапуск. Логи не должны содержать токенов или имён присланных файлов; перед отправкой логов всё равно проверяйте их.

## 4. Проверка после установки

1. Отправьте `/start`: ожидается текст из `greeting`.
2. Отправьте фото и короткое видео менее лимита. Дождитесь «Сохранено.», проверьте содержимое Google Drive / Telegram media / ваш ID.
3. Перезапустите службу, отправьте ещё фото: оно должно добавиться в ту же папку.
4. Отправьте PDF или текст: ответа и нового файла быть не должно.
5. От второго аккаунта проверьте отдельную папку либо отказ в доступе, если задан список ID.

Ошибка Google: проверьте Drive API, квоту, OAuth audience/status, ID папки и права. Отозванный/истёкший token требует повторной авторизации; не публикуйте token для диагностики. Для восстановления после ограничения systemd: `sudo systemctl reset-failed botimagessave`, затем `start`.

## 5. Остановка, обновление, удаление и переустановка

Из каталога клона:

```bash
sudo bash scripts/manage.sh stop       # остановить и выключить автозапуск
git pull --ff-only                     # получить проверенное обновление
sudo bash scripts/manage.sh reinstall  # обновить программу/зависимости, сохранить настройки
sudo bash scripts/manage.sh start
```

`install`/`reinstall` останавливают службу и не запускают её до явного `start`. При неудачной установке исправьте ошибку и повторите. Конфигурация не перезаписывается.

```bash
sudo bash scripts/manage.sh uninstall  # удалить службу, venv и программу
# Если нужно удалить также локальные настройки, token и системного пользователя:
sudo bash scripts/manage.sh purge --confirm
```

Клон Git и файлы в Google Drive сохраняются. Клон можно удалить отдельно после проверки своих файлов. Для полной отмены доступа откройте Google Account → Security → Third-party connections и отзовите приложение; токен Telegram отзовите в BotFather. После purge для переустановки повторите install, загрузите token и заполните TOML.

## Совместимость и ограничения безопасности

Бот не меняет 3x-ui, Xray, firewall, маршрутизацию, nginx или существующие службы; не слушает входящие порты. Нужен исходящий HTTPS к `api.telegram.org`, `oauth2.googleapis.com`, `www.googleapis.com` (и Google OAuth с локального компьютера). Не используйте токены/учётные записи 3x-ui. Установщик меняет только собственные `/opt/botimagessave`, `/etc/botimagessave`, unit и системного пользователя. Перед выполнением проверьте, что эти имена не заняты другой программой.

Отдельный непривилегированный пользователь, systemd sandbox, закрытые права на секреты, временные файлы с удалением, последовательная обработка, лимиты CPU/RAM. Google HTTP-клиент использует TLS с проверкой сертификатов. Медиа не запускаются и не перекодируются. Проверка заголовка не является антивирусом; не открывайте недоверенные файлы без проверки. Без списка разрешённых ID посторонние могут расходовать вашу квоту. Абсолютной гарантии безопасности и отсутствия влияния на общие ресурсы нет; контролируйте свободный диск/RAM и обновляйте Ubuntu и зависимости.

Нет гарантии exactly-once: при сбое между сохранением и подтверждением возможен повторный файл; при длительном простое Telegram хранит обновления ограниченное время (обычно до 24 часов). Повторно отправленные файлы сохраняются как новые. Папки бота не следует удалять/перемещать во время работы. Размер очереди Telegram и квоты API ограничивают нагрузку; решение предназначено для небольшого личного архива.

## Разработка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
BOT_CONFIG=/абсолютный/путь/config.toml .venv/bin/python bot.py
```

Не запускайте два экземпляра с одним токеном. Модульные тесты не обращаются к Telegram/Google. Реальная end-to-end проверка требует ваших credentials и проводится по разделу 4.
